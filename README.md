# 抖音（桌面版）

把抖音网页版装进一个干净的桌面窗口，并内置「抖音优化」用户脚本：视频过滤、屏蔽登录弹窗、
自定义清晰度、禁止自动播放、自动进入全屏、屏蔽弹幕与礼物特效等。

> 维护者与 AI agent 请看 [AGENTS.md](AGENTS.md) —— 项目结构、约定、测试与排查手册都在那里。

## 下载

从 [Releases](https://github.com/yhgeo/douyin-desktop/releases) 下载 `x.y.z-setup.exe`，双击安装。
单用户安装，**不需要管理员**，安装时可以自选目录。

窗口打开后先是 logo 加「正在加载…」，随后换成抖音网页版 —— 这一步是正常的，不是卡住。

**启动很快**：装完第一次打开约 2.8 秒（Windows Defender 要扫描刚写入的文件），之后每次约 0.3 秒。

> 以前还发过一个「便携版」单文件，已经停掉了：它每次启动都要把整个程序（约 470 MB）解压到
> `%TEMP%` 再运行，实测到窗口出现要 15.7 秒，而且**每次都慢** —— 它每次解出来的都是新文件，
> 所以每次都要重新被扫描一遍。安装版没有这个问题。

## 第一次使用

1. 双击运行，窗口打开抖音网页版；用扫码或短信登录（登录状态会保留）。
2. 顶部菜单 **抖音优化** 可以启用 / 停用脚本、打开配置界面（`Ctrl+,`），以及导出 / 导入配置。

## 包含什么

- 独立的抖音桌面窗口，登录状态、Cookie 与网页数据持久化
- 前进 / 后退 / 刷新 / 主页 / 缩放 / 全屏
- 内置「抖音优化」脚本及其依赖，尽量兼容脚本用到的 GM 存储、请求、下载与菜单 API
- 全中文菜单、应用名与图标
- 拦截 `bytedance://` 等未安装的外部协议，避免 Windows 弹出"选择应用"窗口
- 「抖音网页数据」与「脚本配置数据」可以分别清除，互不影响
- 脚本配置支持导出到文件 / 从文件导入，便于备份与换机器

## 菜单一览

| 菜单 | 内容 |
| --- | --- |
| 导航 | 抖音首页、后退 / 前进、刷新 |
| 抖音优化 | 启用 / 停用脚本、打开配置界面（`Ctrl+,`）、移动端配置、导出 / 导入配置，以及脚本自己注册的菜单项 |

| 工具 | **关闭卡住的弹窗**、**修复无法加载的页面**、**关闭「移除某些Cookie」**、**打开运行日志**、清除抖音网页数据…、清除脚本配置数据…、开发者工具、退出 |
| 帮助 | 使用说明、抖音优化脚本主页、项目仓库、**关于**（版本与数据目录） |

**工具菜单按"你要做什么"排序**：先是可以救场的操作，然后是日志（出问题时好反馈），再是清除数据，
开发者工具放最后。清除类带 `…` 表示会先弹确认。

**帮助 → 关于** 显示版本和**数据目录**，并可以一键打开它 —— 备份和反馈问题时都在这里找。

## 遇到问题

**窗口黑屏，一直加载不出来**

**先点 工具 → 关闭「移除某些Cookie」（黑屏的已知原因）**，然后重新加载页面。

这是最常见的原因，而且症状很好认：**第一次打开正常，第二次就黑屏**。

脚本的这个开关会在每次加载时删掉抖音的反爬签名 cookie（`__ac_signature` / `__ac_referer` /
`__ac_nonce`）。这些 cookie 是服务器发给**你这个客户端**的凭证；删掉之后，下一次请求就成了
"服务器认得你、但你没有签名"，于是服务器返回一个空页面。**在浏览器里刷抖音没事，正是因为
浏览器不会删这些 cookie。**

菜单里点一下就关掉了（也可以到 **抖音优化 → 配置界面** 里关）。脚本自己的默认值本来就是关的，
它的说明也写着"阻止触发验证弹窗（maybe）"—— 是个猜测性的规避开关。

如果关掉之后还是黑的：

- 正常加载时窗口会显示 logo 和「正在加载…」。**一直是纯黑、没有任何文字**才是出问题了。
- 点 **工具 → 修复无法加载的页面**：清掉网页的临时数据后重新加载，**不会掉登录**。
  多数情况应用会自己修好 —— 检测到页面为空就自动按阶梯重试，窗口标题会显示「正在自动修复（第 N 次）」。
- 启动日志里也会写明这个开关是否开着（`工具 → 打开运行日志`）。

**全屏时画面模糊**

开启「屏蔽 搜索悬浮栏」或「屏蔽 网页全屏关闭按钮」后，推荐页**第三个视频起**在全屏状态下会变成一片模糊。

原因：脚本用 `:has()` 选择器屏蔽这两个元素，而 `:has()` 会匹配**任意包含该图标的祖先元素** ——
结果命中了装着 `<video>` 的播放器层，把它 `display:none` 掉。剩下的只有播放器自带的毛玻璃背景图
（`filter: blur(60px)`），看起来就是"超级模糊"。

程序会在检测到这条规则真的藏住了视频时把它移除（日志里会有一条「已移除会隐藏视频的样式规则」），
所以这两个开关现在可以正常使用。**如果你看到模糊，请升级到 0.2.5 或更高版本。**

**窗口标题显示「服务器暂时没有返回页面」**

服务器端没给页面，不是本地坏了。重试间隔会自动放长（15 秒 → 1 分钟 → 3 分钟 → 5 分钟 → 10 分钟），
**间隔这么长是故意的** —— 重试本身就是一次请求，太频繁反而让服务器更不愿意响应。
**不要反复重启**：每次重启都是一次新请求。耐心等十几分钟通常就好了。

**窗口标题显示「服务器要求人机验证」**

抖音要求完成一次人机验证（通常是短时间内请求过于频繁）。清数据、重装都没有用，等几分钟再打开。
提示会在页面恢复可用后自动消失；应用只在服务器确实要求验证时才显示它。

**弹窗点不动了**

「是否保存登录信息？」这类弹窗偶尔会卡在按钮转圈的状态，整页点不动。
应用会在约 1 秒内自动关掉它，也可以手动 **工具 → 关闭卡住的弹窗**。

**双击后一闪而过，窗口起不来**

Chromium 的 GPU 子进程启动失败导致主进程中止，与应用逻辑无关。重启机器一般即可恢复；
用 `npm start` 运行的话可以先加 `--in-process-gpu`。

**想反馈问题**

**工具 → 打开运行日志**，最前面几行记录了版本、运行方式与数据目录；连同日志一起提供会省很多时间。

## 数据放在哪里

登录状态、网页数据、脚本配置、运行日志都在同一个目录里：

| 版本 | 数据目录 |
| --- | --- |
| 安装版 | `<安装目录>\data`（安装时你自己选的那个目录） |
| 开发运行（`npm start`） | `%APPDATA%\douyin-desktop` |

目录里面的文件：

| 内容 | 文件 |
| --- | --- |
| 登录状态、网页数据 | `data\`（Chromium 的 profile） |
| 脚本配置 | `data\userscript-config.json` |
| 运行日志 | `data\logs\main.log` |

**首次运行时，如果 `%APPDATA%\douyin-desktop` 里有旧数据，会自动复制一份过去**，
登录状态与脚本配置一并保留（旧目录不会被动）。只复制不可再生的部分，缓存不复制，所以这一步很快。

> **备份就是复制整个 `data` 文件夹。**
> 注意：数据在安装目录里，所以**卸载会连同数据一起删除**；`%APPDATA%\douyin-desktop`
> 里那份旧数据不受卸载影响。

> **不要同时开两个。** 同一个数据目录被两个进程写会损坏它，登录状态与脚本配置都在那份数据里。
> 开第二个时它会立刻退出，并把已有窗口唤到最前。

日志会自动轮转：单个文件上限 2 MB，保留 2 份历史，也就是最多约 6 MB。你不需要手动清理。

「清除抖音网页数据」只清登录与网页数据（保留脚本配置）；「清除脚本配置数据」只清脚本配置
（保留登录）。想换机器时用「导出配置到文件」。

## 脚本来源与许可

脚本源码保存在 `assets/douyin-optimization.user.js`，其依赖的 UMD 文件保存在 `vendor/`。
更新脚本前请阅读并遵循上游项目的许可与发布要求。
