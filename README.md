# 抖音（桌面版）

把抖音网页版装进一个干净的桌面窗口，并内置「抖音优化」用户脚本：视频过滤、屏蔽登录弹窗、
自定义清晰度、禁止自动播放、自动进入全屏、屏蔽弹幕与礼物特效等。

> 维护者与 AI agent 请看 [AGENTS.md](AGENTS.md) —— 项目结构、约定、测试与排查手册都在那里。

## 下载

从 [Releases](https://github.com/yhgeo/douyin-desktop/releases) 下载 `x.y.z-setup.exe`，双击安装。
单用户安装，**不需要管理员**，安装时可以自选目录。

装完第一次打开约 2.8 秒（Defender 要扫描刚写入的文件），之后每次约 0.3 秒。

## 第一次使用

1. 双击运行，窗口打开抖音网页版；扫码或短信登录（登录状态会保留）。
2. 顶部菜单 **抖音优化** 可以启用 / 停用脚本、打开配置界面（`Ctrl+,`），以及导出 / 导入配置。

## 包含什么

- 独立的抖音桌面窗口，登录状态、Cookie 与网页数据持久化
- 前进 / 后退 / 刷新 / 主页 / 缩放 / 全屏
- 内置「抖音优化」脚本及其依赖，兼容脚本用到的 GM 存储、请求、下载与菜单 API
- 全中文菜单、应用名与图标；拦截 `bytedance://` 等未安装的外部协议
- 「抖音网页数据」与「脚本配置数据」可以分别清除，互不影响
- 配置可导出 / 导入，也可以一键套用内置预设

## 菜单一览

| 菜单 | 内容 |
| --- | --- |
| 导航 | 抖音首页、后退 / 前进、刷新 |
| 抖音优化 | 启用 / 停用脚本、打开配置界面（`Ctrl+,`）、移动端配置、导出 / 导入配置、**预设配置**，以及脚本自己注册的菜单项 |
| 视图 | 放大 / 缩小 / 恢复缩放、全屏 |
| 工具 | **关闭卡住的弹窗**、**修复无法加载的页面**、**关闭「移除某些Cookie」**、**打开运行日志**、**保存当前画面（截图）**、**记录播放器诊断**、清除抖音网页数据…、清除脚本配置数据…、开发者工具、退出 |
| 帮助 | 使用说明、抖音优化脚本主页、项目仓库、**关于**（版本与数据目录） |

**工具菜单按"你要做什么"排序**：先是可以救场的操作，然后是日志（出问题时好反馈），再是清除数据，
开发者工具放最后。清除类带 `…` 表示会先弹确认。

**帮助 → 关于** 显示版本和**数据目录**，并可以一键打开它 —— 备份和反馈问题时都在这里找。

### 预设配置

**抖音优化 → 预设配置** 里是一组现成的整套开关，点一下就把全部配置换成它（会先备份当前配置，
再刷新页面）。内置了一个「精简浏览（屏蔽较全）」。

想加自己的预设：**预设配置 → 打开预设文件夹**，把一份**导出的配置备份**（`.json`）放进去，
重启应用即可在菜单里看到。文件名就是菜单里显示的名字，也可以在文件里加 `"name"` 和
`"description"` 两个字段自定义。

### 记录播放器诊断

排查"画面不对"这类问题时用：**工具 → 记录播放器诊断**，然后照常刷几个视频（全屏、切换视频、
鼠标进出播放器都算），复现之后打开运行日志，搜「播放器诊断」即可。

每条记录包含当时是否全屏、视频分辨率与显示尺寸、`object-fit`、控件透明度、模糊背景层是否存在
及其显隐状态、左右两侧实际是什么元素。默认关闭，最多记 600 条。

## 遇到问题

**窗口黑屏，一直加载不出来**

**先点 工具 → 关闭「移除某些Cookie」（黑屏的已知原因）**，然后重新加载页面。

判据很好认：**第一次打开正常，第二次就黑屏**。脚本的这个开关会在每次加载时删掉抖音的反爬签名
cookie，服务器随后返回空页面 —— 在浏览器里刷抖音没事，正是因为浏览器不会删这些 cookie。

如果关掉之后还是黑的：

- 正常加载时窗口会显示 logo 和「正在加载…」。**一直是纯黑、没有任何文字**才是出问题了。
- 点 **工具 → 修复无法加载的页面**：清掉网页临时数据后重新加载，**不会掉登录**。
  多数情况应用会自己修好，窗口标题会显示「正在自动修复（第 N 次）」。
- 启动日志里会写明这个开关是否开着（`工具 → 打开运行日志`）。

**全屏时画面模糊**

开启「屏蔽 搜索悬浮栏」或「屏蔽 网页全屏关闭按钮」后，推荐页第三个视频起在全屏下会变成一片模糊：
脚本的 `:has()` 选择器命中了装着 `<video>` 的播放器层。程序会在检测到这条规则真的藏住了视频时
把它移除（日志里有一条「已移除会隐藏视频的样式规则」）。**看到模糊请升级到 0.2.5 或更高版本。**

**窗口标题显示「服务器暂时没有返回页面」**

服务器端没给页面，不是本地坏了。重试间隔会自动放长（15 秒 → 1 分钟 → 3 分钟 → 5 分钟 → 10 分钟），
**间隔这么长是故意的**。**不要反复重启**，每次重启都是一次新请求，等十几分钟通常就好。

**窗口标题显示「服务器要求人机验证」**

抖音要求完成一次人机验证（通常因为请求过于频繁）。清数据、重装都没用，等几分钟再打开；
提示会在页面恢复后自动消失。

**弹窗点不动了**

「是否保存登录信息？」这类弹窗偶尔会卡在按钮转圈的状态，整页点不动。应用会在半秒左右自动关掉它，
也可以手动 **工具 → 关闭卡住的弹窗**。

**双击后一闪而过，窗口起不来**

Chromium 的 GPU 子进程启动失败，与应用逻辑无关。重启机器一般即可恢复；用 `npm start` 运行时
可以先加 `--in-process-gpu`。

**想反馈问题**

**工具 → 打开运行日志**，最前面几行记录了版本、运行方式与数据目录。

画面类问题（黑边、模糊、颜色不对）请这样取证，两样一起发过来最有用：

1. **工具 → 记录播放器诊断** 打开开关；
2. 复现到画面不对的那一刻，点 **工具 → 保存当前画面（截图）**；
3. 把 `data\logs\` 里的 `capture-<时间>.png` 和当天的日志一起发过来。

## 数据放在哪里

登录状态、网页数据、脚本配置、运行日志都在同一个目录里：

| 版本 | 数据目录 |
| --- | --- |
| 安装版 | `<安装目录>\data`（安装时你自己选的那个目录） |
| 开发运行（`npm start`） | `%APPDATA%\douyin-desktop` |

| 内容 | 文件 |
| --- | --- |
| 登录状态、网页数据 | `data\`（Chromium 的 profile） |
| 脚本配置 | `data\userscript-config.json` |
| 运行日志 | `data\logs\main-<日期>.log`（按天分文件，保留 7 天） |

**首次运行会把 `%APPDATA%\douyin-desktop` 里的旧数据复制过去**（旧目录不动，缓存不复制，很快）。

> **备份就是复制整个 `data` 文件夹。** 数据在安装目录里，**卸载会连同数据一起删除**。

> **不要同时开两个。** 同一个数据目录被两个进程写会损坏它。开第二个时它会立刻退出，
> 并把已有窗口唤到最前。

日志自动轮转：单文件上限 2 MB，保留 2 份历史，最多约 6 MB，不需要手动清理。

## 脚本来源与许可

内置脚本来自 `WhiteSevs/TamperMonkeyScript`，标注为 **GPL-3.0-only**。
脚本源码在 `assets/douyin-optimization.user.js`，依赖的 UMD 文件在 `vendor/`。
更新脚本前请阅读并遵循上游项目的许可与发布要求。

可选的「体验增强」脚本是 Frequenk 的[网页抖音体验增强](https://greasyfork.org/zh-CN/scripts/539942) 5.7（标注 GPL-3.0），
源码在 `assets/douyin-experience-enhancer.user.js`，相对原版只做了两处桌面版适配（工具栏开关跨刷新保留、倍速菜单悬停层级）。默认关闭，在菜单「体验增强」里开启。
